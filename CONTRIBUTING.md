# Contributing

Use synthetic or rights-cleared examples. Keep actual research notes, identity information, and private papers out of commits and screenshots.

Changes to scheduling or import validation should include a failing example and a meaningful core test. Run `node --test tests/*.test.mjs`, then exercise the affected behavior in a browser at desktop and mobile widths. Preserve keyboard access, plain-language errors, and atomic save/import behavior.

Do not describe a rule-based feature as a model prediction, or a user-entered artifact link as verified evidence. New model integrations need explicit user control and an accurate account of where research data is sent.
